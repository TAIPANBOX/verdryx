# verdryx 0.2.0

verdryx is the quality plane of the estate. Until now `drift` and `slo` printed a verdict and forgot it. In 0.2.0 a quality failure becomes a record an operator comes back to, a fix can be registered against it and judged by the runs that follow, and a person can grade a case in a way the model's score cannot overrule. All of it is deterministic: no model, no network, no new event type on the bus.

verdryx is still a command-line tool, not a server. It is not on PyPI, and there is no container image or binary; install it from the repository as the README describes. The suite collects 739 tests, and the README badge states the same number.

## What changed (#58 to #60)

**Findings**

- #60 A `drift` regression, or an `slo` breach the confidence interval establishes (the bar the bus already uses), is stored as a finding: agent, window, kind (`drift`, `slo_exhausted`, `slo_fast_burn`), evidence (run ids, the lowest scoring cases, the gateway runs that failed an indicator) and a suspect model or version. The suspect says which of three things it is: a change, no change across N runs, or too few runs to compare. `verdryx eval --agent-version` stamps a run with the version under test. The same failure seen again is one finding seen again (`dedupe_key`). `verdryx findings list|show`.

**Fix verification**

- #60 `verdryx findings fix ID --note ... [--version V]` registers a fix. The next `drift` or `slo` decides it from the runs that started after it. Measured and clean is `verified` and the finding closes. Measured and still failing is `failed`: the finding reopens and the attempt stays on record with its numbers. Anything short of a measurement stays `pending` with its reason (no run since, too few runs, runs of another version, an interval that still covers the target). A fix draws a line in time: runs from before it neither verify it nor undo it, and a closed finding is not reopened by the runs it was closed over. Unmeasured is never a pass.

**Human grades**

- #60 `verdryx grade RUN CASE VALUE --author NAME --key-file PATH` writes a person's grade. It replaces the model's value in a run's mean, in drift and in the quality floor, and the model's own value is kept beside it. A later grade supersedes an earlier one and both stay on record.
- Every grade carries its author: a principal registered with `verdryx principal add`, whose generated key is written once (mode 0600) and stored as a hash. The role `reviewer` can grade; the role `uploader` cannot. `verdryx eval` needs no credential and has no path to a grade. `scripts/human-grades-have-one-door.sh` reads the package for exactly one INSERT into `human_grades`, inside `Store.add_human_grade`, called only from `_cmd_grade`. The store file remains the trust boundary.

**Events and drift**

The typed grader was run end to end against typryx v0.5.1 (backend `openai-logprobs`, `qwen2.5:7b` behind Ollama), and the run found four defects on the path from a score to the bus. All four are fixed, each reproduced first.

- #59 `drift` printed `regressed` and wrote nothing to the bus when no `--agent-id` was typed, although `eval --agent-id` had stored the agent on the run. It now uses the agent stored with the newest run of the window.
- #59 `eval --events` with no agent id wrote an empty bus and said nothing. `eval` and `drift` now say on stderr how many events were not written, to which file and why.
- #59 `drift` named the oldest run of a window wider than one. It now names the newest.
- #59 A typryx behind a slow model made verdryx give up after a fixed 30 s with `could not reach typryx`. The error now says `did not answer within Ns`, and `eval` has `--typed-timeout SECONDS`.
- #59 `slo_burn` carried `burn_rate: 0.0` for an agent whose rate nobody measured, with nothing to tell it from a measured zero. The event now carries `burn_events_seen`, the count behind the rate.

**Price book**

- #58 Mirrors `gpt-6.1-terra` and its `openai/` twin from TokenFuse's default price book: 1.00 / 5.00 / cache read 0.05 / cache write 1.25 USD per 1M tokens, and above 272,000 prompt tokens 2.00 / 7.50 / 0.10 / 2.50. Before this, verdryx charged the model at the fallback rate.

**CI**

- #57 The actions group is bumped: `actions/setup-python` 7.0.0 to 7.1.0, `ossf/scorecard-action` 2.4.4 to 2.5.0, `github/codeql-action/upload-sarif` 4.38.3 to 4.39.1.

**Gates and documentation**

- #59 CLAUDE.md invariant 13: an event log the operator switched on never takes nothing in silence. Held by tests, each run red against the unfixed code first.
- #60 CLAUDE.md invariants 14 (a person's grade outweighs the model's and is written through one door) and 15 (a finding is computed from the stores and traces alone, and a fix is decided by a measurement).
- #60 `features/findings.feature` (13 scenarios), `features/fix-verification.feature` (14) and `features/human-grades.feature` (12), every scenario bound to a test. `scripts/gates-have-teeth.sh` is 27 cases, six of them for the new human-grade gate.
- #60 `components.json` declares the `findings`, `grade` and `principal` subcommands and `VERDRYX_REVIEWER_KEY_FILE`.
- Coverage of the `verdryx` package is 98% (2164 of 2211 statements), printed in CI and not gated.

## Breaking

None. The CLI changes are additions (the `findings`, `grade` and `principal` subcommands, `eval --agent-version` and `eval --typed-timeout`). No event type was added or changed, and the event envelope is untouched. The only change to an event is one added key in the open `data` of `slo_burn`.

## Migration

- **Store upgrade is in place.** Opening an older store with this build creates the tables `findings`, `fixes`, `principals` and `human_grades` and adds the nullable column `eval_runs.agent_version`. `PRAGMA user_version` stays at 1. No manual step is needed.
- **A console that reads `scores` directly shows the model's value, not a person's, until it also reads `human_grades`.** The Genaryx console reads the stores through verdryx; any other reader of the `scores` table needs the same join.
- **A consumer of `slo_burn` events can read `burn_events_seen`.** A `burn_rate` of `0.0` with `burn_events_seen` of `0` means the rate was never measured, which is the opposite of a fleet burning nothing.
- **`drift` now writes its event when `--agent-id` is not given**, taking the agent stored with the newest run of the window. A bus that stayed empty after a regression before will now carry the event.
- **Judge cost estimates for `gpt-6.1-terra` changed** from the fallback rate to the mirrored price book rate. Compare costs across that change with this in mind.
