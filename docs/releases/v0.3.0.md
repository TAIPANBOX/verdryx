# verdryx 0.3.0

verdryx is the quality plane of the estate. In 0.3.0 `verdryx slo` measures the window it names, and a deployment whose policy plane holds an agent on these events can keep a hold from spending the budget that caused it. Both came from running the command on a real trace, ahead of connecting it to wardryx in both stacks.

verdryx is still a command-line tool, not a server. It is not on PyPI, and there is no container image or binary; install it from the repository.

## What changed (#64)

**The window is real**

- `--window` was a label. Every run in the directory counted for as long as the trace was kept, so a budget spent once stayed spent. It now leaves out the runs and scores that ended before it, and the report says how many.
- A run that carries no time stays in and is counted, because nothing says it is old.
- A window is a whole number of hours, days or weeks (`6h`, `28d`, `2w`). Anything else is refused.

**A hold need not spend the budget that caused it**

- `wardryx_hold` is a refusal to `containment`, and a held call is written to the trace. With wardryx holding an agent on `slo_burn`, each held call spent more of the budget, and an agent still working could never earn it back.
- `verdryx slo --holds-spend-no-budget` sets holds apart. A run only a hold stopped meets containment, and every other refusal still counts. The trace records that a call was held, not which rule held it, so the switch sets every hold apart.
- A per-run record now carries `held_calls`, the `wardryx_hold` part of `refused_calls`.

## What an upgrade changes

A report over an old trace now covers the last 28 days unless you pass `--window`, so it can show fewer runs than before. A label that is not a number of hours, days or weeks, which 0.2.0 printed and ignored, now stops the command. The report's default for holds is unchanged.
